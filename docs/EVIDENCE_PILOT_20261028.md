## 2. 标注契约与检查

新增 `evaluation/evidence_cases.py`，在运行试点前检查：

| 检查 | 拦截内容 |
| --- | --- |
| 参数与标签结构 | 未知字段、空答案、重复题目、重复证据、可回答但没有证据 |
| 论文范围 | 证据不属于题目指定的 paper_scope |
| 集合划分 | 同一 DOI（忽略大小写）、论文 ID 或原始草案模板跨 development/holdout |
| 冻结指纹 | 问题、标签、答案、限制或证据被修改后未更新清单 |
| 规范证据身份 | chunk_id 不存在、论文或页码错配 |
| 正文与短引 | 正文指纹变化、短引不在规范正文中 |
| 原文件版本 | 可选检查本地 PDF 的 SHA256 是否与审查时一致 |

语料读取使用 SQLite `mode=ro` 和 query_only，不新建数据库、不下载、不调用模型。检查错误码不回显提供方原始异常。

当前不允许把“检查过的几页未找到”标为整篇论文或全库无证据；insufficient_evidence 的金标准缺少完整缺失检索契约，暂时拒绝入集。未指定目标论文的两题仅有澄清目标，不填伪造的 gold evidence，也不进入检索召回分母。

JSON 语义指纹对键顺序和 CRLF/LF 换行保持稳定；内容变更仍失效。冻结是一致性约束，不是防篡改签名或专家认证。短引匹配不能证明期望答案的语义支持。

## 3. 只读核验与关键词基线

```powershell
python -m evaluation.evidence_cases `
  --dataset data/evaluation/evidence_pilot_20261028.jsonl `
  --manifest data/evaluation/evidence_pilot_20261028.manifest.json `
  --database data/research.db --papers-dir data/papers `
  --keyword-baseline --output artifacts/evidence_pilot_local.json
```

输出路径必须未存在，避免覆盖既有报告。完整核验需要与清单一致的本地语料和 PDF；克隆仓库后运行单元测试不需要这些个人数据。

本地核验结果：8 题、7 个规范证据块、2 份 PDF 指纹一致。报告为 `artifacts/evidence_pilot_audit_20261028.json`。

原有 FTS5 关键词链路在每题指定的论文范围内，前 5 位的指定证据块平均覆盖为 **25.00%**（6 条证据题；2 条澄清题排除；检索执行失败 0）。单题结果依次为 0、0、0、1、0.5、0。原始结果保存在 `artifacts/evidence_pilot_keyword_20261028.json`。

解释限制：

- 这是 6 条开发题的“指定证据块覆盖”，不是全部相关证据的穷尽召回率。其他段落也可能提供有效答案，未自动判错。
- 题目已有论文范围，因此也不是全库论文发现能力评估。
- 当前没有运行向量、混合检索、重排或真实模型回答对照。
- 不能与旧 48 题的关键词基线直接比较；题集、分母和标注粒度均不同。
- 本批未针对这 6 题调参。低覆盖用来定位下一阶段问题，不修改 gold 以追求更高分数。
