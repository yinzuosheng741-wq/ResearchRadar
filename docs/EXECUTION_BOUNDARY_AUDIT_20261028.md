# 检索执行边界复查（2026-10-28）

## 实际问题与修复

上层 QA、研究路线和 Skill 执行器已区分执行失败与证据不足，但底层仍有三处宽泛异常降级：混合检索分支、两阶段检索的可选全局分支、邻域上下文加载。这些位置可能把 `ExecutionDenied` 当作普通服务故障吞掉，继续调用其他分支或返回已有证据。

- 三处均显式传播策略拒绝，由 Skill 边界返回 `blocked` 和稳定错误码；不将其改成检索故障或知识库无证据。
- 混合检索在每个分支前后检查共享截止时间。首个分支迟到返回或迟到抛错，都不启动第二个分支。
- 规范正文加载及可选邻域加载增加截止检查，过期后不继续扩展上下文。
- 普通供应商故障仍可保留另一分支证据；普通邻域故障仍可保留规范锚点；普通全局补召回故障仍可保留论文内检索结果。空显式范围仍不发起检索。

## 检查范围与验证

复查请求上下文、Skill 执行、QA/研究路线、检索与上下文、引用边界、对话遗忘与项目记忆、前端范围选择及服务装配，并运行完整既有测试（含 UI）。这不代表人工审阅所有文件，也不代替真实模型和真实向量检索验收。

新增 15 项离线回归，通过实际 `QA/研究路线 → HybridRetriever → 分支 → SkillExecutor` 组合验证拒绝传播，并覆盖迟到成功/失败、调用前过期、可选全局分支、邻域及规范正文边界，以及普通故障降级。未执行付费模型。

全量 452 项通过、1 项目录符号链接环境跳过；修改模块与新增测试 E4/E7/E9/F/I、编译及健康检查通过；保留既有 langchain-community 弃用提示。

## 边界与后续

`search_calls` 仍表示协调器层面的逻辑检索，不等同于底层 SQL、向量请求或网络往返数量；本次没有改变计费口径。同步调用无法强制取消已执行的 SDK 请求，截止检查拒绝迟到输出并阻止后续工作，不保证 90 秒内立即返回。

本批不改原始论文、向量索引、冻结题集、检索排名策略或界面样式；未声明召回率提升。下一步优先增加不同论文与真实问题的独立标注，评估全文证据覆盖、双语检索及引用支持程度，再决定是否值得增加重排或任务执行基础设施。
